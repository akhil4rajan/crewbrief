## Testing

* Keep unit testing minimal to save tokens and time. Do not write new unit
tests or test suites for features by default.
* Verify changes by running the app or a quick manual/smoke check instead.
* Only add a test if the user explicitly asks, or for a bug that is hard to
verify any other way.
* Do not spend time fixing or extending existing tests unless they block a build.

## Branching

* Never commit work directly to `main`.
* Every feature, fix, or chore gets its own feature branch, created from the
latest `main`. There is no `dev` branch; do not create or use one.
* If a feature depends on another branch that is not merged yet, branch from
that feature branch instead and state the merge order when handing over.
* Branch names must be plain and readable: `<type>/<short-description>` in
lowercase kebab-case. Examples:

  * `feature/user-login`
  * `feature/match-history-page`
  * `fix/score-calculation`
  * `chore/update-readme`
* No random IDs, session hashes, or fancy or cryptic names.
* Keep one concern per branch. Open a pull request only when asked.
